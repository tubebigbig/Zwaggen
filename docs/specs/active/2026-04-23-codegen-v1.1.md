# Spec — Codegen v1.1: folder-key sanitization, inline types, async headers, tag camelization

## Problem

Codegen v1 shipped a working `zwag generate ts` / `generate zod` flow but the v1 final code review surfaced four ergonomics gaps that any real spec will hit:

1. **Folder-prefixed type keys break.** Once a user organizes types into folders (the DnD feature shipped in slice 2026-04-22), keys carry `/` separators (`auth/User`, `billing/Invoice`). The codegen emits these verbatim, producing invalid TypeScript: `export interface auth/User {}` won't parse. Today the only workaround is to flatten the spec before codegen — defeats the point of folders.

2. **Inline `requestBody` and param object types fall through to `unknown`.** When an endpoint declares its request body or a path/query/header parameter as an inline `{ kind: 'object', fields: [...] }` instead of a `$ref`, the client emits `unknown` for the type. Users lose all autocomplete and type checking. Workaround today: extract every inline object into a top-level named type — viable but tedious.

3. **`opts.headers` is sync-only.** `createClient({ headers: () => ({ Authorization: 'Bearer ...' }) })` returns a fresh value on every call but cannot be async. Token-refresh flows that need to call out to an OIDC endpoint or read from a secure store can't use this hook — they have to rebuild the client on every refresh, or wrap fetch externally.

4. **Tag-grouped client API uses bracket access for non-identifier tags.** `tag = "user-management"` produces `client["user-management"].listUsers()`. Verbose, no autocomplete chain after the bracket. `client.userManagement.listUsers()` is what every other generator does (Stainless, OpenAPI Generator, Orval).

These are bounded fixes — same module (`packages/cli/src/generate/`), same surface (TS source output), no schema changes. Bundle them into one v1.1 slice.

## Success criteria

- **Folder-key sanitization**:
  - Type keys containing `/` are sanitized to a valid TS identifier by replacing each `/` with `_`. So `auth/User` → `auth_User`, `billing/v2/Invoice` → `billing_v2_Invoice`.
  - The schema's original key is preserved for `$ref` lookup; the sanitized name is what appears in emitted TS / Zod / client code.
  - Refs to a folder-prefixed type in the schema resolve to the sanitized name in generated code: `extends: ['auth/User']` becomes `export interface Admin extends auth_User`.
  - Collisions between two folder-paths that sanitize to the same name are detected and the codegen exits with a clear error (e.g. `auth/User` and `auth_User` both → `auth_User`). Acceptable for v1 because users would have to actively engineer a collision.
- **Inline object expansion**:
  - `requestBody` / path-param / query-param / header types declared as `{ kind: 'object', fields: [...] }` are emitted as inline TS object literals in the client method's `input` type AND in the typed return shape, instead of `unknown`.
  - Nested inline objects are expanded recursively. Optional fields use `?:`, required fields use `:`.
  - Inline arrays of inline objects work: `{ items: { foo: string }[] }`.
  - Refs inside inline objects (`{ user: $ref User }`) resolve to the named type (or sanitized name).
- **Async headers**:
  - `ZwaggenClientOptions.headers` accepts `Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)`. Existing sync usages stay valid.
  - The generated `baseHeaders()` helper inside `createClient` becomes async (`async () => ...`); every call site `await`s it.
  - The fetch-options builder passes `await baseHeaders()` into the headers object.
  - Tests confirm: sync object, sync fn, async fn all produce a request with the merged headers; failure inside the async fn rejects the client method (the `ZwaggenHttpError` path is unaffected).
- **Tag camelization**:
  - Tag groups in the client root are camelCase: `user-management` → `userManagement`, `auth services` → `authServices`, `v1/users` → `v1Users`, `Admin` → `admin` (first-char lowercase).
  - The default tag (when `endpoint.tags` is empty) stays `default`.
  - Camelized name then runs through `safeIdentifier` for TS-keyword/safety checks. Reserved-word tags (`class`, `import`) fall back to bracket access (`client['class']`) — degenerate case, still parseable, no regression vs v1.
  - Endpoints inside the group are unchanged (already camelized in v1 via `methodNameFor`).
- **All existing codegen v1 tests pass unchanged.**
- New tests:
  - Folder-key fixture (`auth/User` extends `User`, used by an endpoint) generates valid TS that compiles.
  - Inline-object fixture (endpoint with `requestBody = { kind: 'object', fields: [...] }`) generates the expanded inline shape.
  - Async-headers test: instantiate `createClient({ headers: async () => ({ Authorization: 'Bearer x' }) })`, mock fetch, assert the request includes the header.
  - Camelized-tag test: endpoint with `tags: ['user-management']` produces `client.userManagement.X()`.
- Codegen v1.1 ticked in TODO; spec + plan moved to `done/`.

## Out of scope

- **Renaming generated method names beyond what v1 already does.** v1 already camelizes endpoint IDs (`get-users` → `getUsers`); v1.1 only adds the same treatment to tags.
- **Headers-per-method override.** `client.users.list({}, { headers: {...} })` is a separate feature.
- **Automatic retry on 401 with refreshed token.** Async headers enable users to BUILD this themselves (their async fn fetches a fresh token); the client doesn't observe response bodies for refresh signals.
- **Discriminated-union or const-enum generation.** Codegen still emits `union` types as TS unions and `enum` as `z.enum(...)`; no v1.1 changes.
- **Markdown / JSDoc on emitted symbols.** Decision deferred — many generators do this, ours doesn't yet, can land in v1.2.
- **Watch-mode behaviour changes.** No changes to file-watching; the same regenerator runs.
- **Path-template handling beyond `{name}`.** OpenAPI's matrix params, label expansion, etc. — out.
- **The `default` tag fallback name** stays as-is; renaming it (e.g., `client.endpoints.X()`) would be a breaking change for v1 users who already adopted the API.
- **Breaking changes to `ZwaggenClientOptions`.** The headers-type widening is purely additive — existing code keeps compiling.
- **Plugin / hook system for users to inject custom emitters.** Future work.
- **OpenAPI/JSON-Schema export changes.** Codegen consumes the Zwaggen spec; the export pipeline is unaffected.

### Folder-key sanitization rule

```ts
// helpers.ts
export function sanitizeFolderKey(name: string): string {
  return name.replace(/\//g, '_');
}
```

Decision: **replace `/` with `_`**, leave segment casing alone. Why not PascalCase the segments?
- Preserves the user's chosen capitalization (`auth/User` → `auth_User`, NOT `Auth_User`).
- Matches what the user already sees in the type panel.
- Trivially reversible by inspection.

Collision detection at the start of `generateTs`/`generateZod`/`generateClient`:

```ts
function detectKeyCollisions(spec: Spec): void {
  const sanitizedToOriginal = new Map<string, string>();
  for (const key of Object.keys(spec.types)) {
    const s = sanitizeFolderKey(key);
    const prior = sanitizedToOriginal.get(s);
    if (prior !== undefined && prior !== key) {
      throw new Error(`Codegen key collision: ${prior} and ${key} both sanitize to ${s}. Rename one.`);
    }
    sanitizedToOriginal.set(s, key);
  }
}
```

Refs use the sanitized name in emitted code; the original-key → sanitized-name map is built once per generation pass.

### Inline object expansion

`tsRefType` in `client.ts` currently returns `'unknown'` for `kind: 'object'`. Replace with recursive expansion:

```ts
function tsRefType(def: TypeDef, spec: Spec): string {
  switch (def.kind) {
    // ... existing cases ...
    case 'object': {
      if (def.fields.length === 0) return '{}';
      const fields = def.fields.map((f) => {
        const opt = f.required ? '' : '?';
        return `${safeIdentifier(f.name)}${opt}: ${tsRefType(f.type, spec)}`;
      }).join('; ');
      return `{ ${fields} }`;
    }
  }
}
```

`tsRefType` already takes a single arg today — this signature widens to also accept `spec` so refs can be resolved to sanitized names. Mechanical update at every call site.

### Async headers

`OPTIONS_INTERFACE`:

```ts
const OPTIONS_INTERFACE = `export interface ZwaggenClientOptions {
  baseUrl: string;
  fetch?: typeof globalThis.fetch;
  headers?: Record<string, string>
    | (() => Record<string, string>)
    | (() => Promise<Record<string, string>>);
}`;
```

`createClient`:

```ts
return HEADER + importLine
  + OPTIONS_INTERFACE + '\n\n'
  + ERROR_CLASS + '\n\n'
  + `export function createClient(opts: ZwaggenClientOptions) {\n`
  + `  const f = opts.fetch ?? globalThis.fetch;\n`
  + `  const baseHeaders = async (): Promise<Record<string, string>> => {\n`
  + `    if (typeof opts.headers === 'function') return await opts.headers();\n`
  + `    return opts.headers ?? {};\n`
  + `  };\n`
  + `  return {\n${groupBlocks.join(',\n')},\n  };\n`
  + `}\n`;
```

Method bodies that today do:

```ts
{ ...baseHeaders()${headerSpread} }
```

become:

```ts
{ ...(await baseHeaders())${headerSpread} }
```

The `async` keyword is already on the method (every emitted method is `async`), so adding `await` inside the headers object literal is the only change. The `headers:` value in `fetch` opts becomes an async-aware computed expression.

### Tag camelization

```ts
// helpers.ts
export function camelizeTag(tag: string): string {
  if (tag === 'default') return 'default';
  const parts = tag.split(/[^A-Za-z0-9]+/).filter(Boolean);
  if (parts.length === 0) return 'default';
  const [first, ...rest] = parts;
  const camelFirst = first!.charAt(0).toLowerCase() + first!.slice(1);
  const camelRest = rest.map((p) => p.charAt(0).toUpperCase() + p.slice(1));
  return [camelFirst, ...camelRest].join('');
}
```

Examples:
- `user-management` → `userManagement`
- `auth services` → `authServices`
- `v1/users` → `v1Users`
- `Admin` → `admin`
- `default` → `default` (preserved)
- `class` → `class` (later wrapped by `safeIdentifier` if it's reserved → bracket access)
- `123-foo` → `123Foo` (would still need `safeIdentifier` since identifiers can't start with a digit; `safeIdentifier` will quote → bracket access)

`groupByTag` in `client.ts` uses `safeIdentifier(camelizeTag(tag))` for the property name.

### Determinism

The pinned prettier config from v1 stays. Re-running `zwag generate ts <fixture>` twice still produces byte-identical output. The byte-equality test in v1 still runs; v1.1 just changes the expected golden bytes.

### Versioning

`@zwaggen/cli` is private and unpublished today; bumping its package.json version isn't strictly required. But bump `0.x.y` → `0.x.(y+1)` so the version string baked into the codegen header is fresh on next publish.

### Risks

- **Existing user code with sync headers** keeps working because the type widening is additive — `Record<string, string> | (() => Record<string, string>)` is still in the union. Test runs the existing fixtures unchanged to confirm.
- **Deeply nested inline objects** could in theory produce very long single-line type expressions. Prettier reformats on its pass. Expect ugly-but-valid output in pathological cases. Document.
- **Folder-key collision from two genuinely different paths** (`a/b_c` and `a_b/c` both → `a_b_c`) is the only realistic clash. Detection throws cleanly. Users can rename one type.
- **Tag with only special chars** (`!!!`) → `parts = []` → falls back to `default`. All endpoints with that tag share the `default` group with any actually-untagged endpoints. Extremely degenerate; document briefly.
- **Async `baseHeaders()` adds an extra await per request**. ~microseconds; user-visible latency unchanged. Net win is correctness for token refresh.
- **The new fixture's expected goldens** are wide diffs in the test file; review carefully so a regression doesn't sneak in. Snapshot inspection is the test owner's responsibility.
