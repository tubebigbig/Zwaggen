# Spec — Zwaggen Desktop slice 2: electron-builder packaging + app icons

## Problem

Slice 1 produced a working local-dev Electron app you can launch with `pnpm --filter @zwaggen/desktop dev`. Nothing is packaged — there's no `.dmg`, no `.exe`, no `.AppImage`. To put builds in users' hands (or even on a developer's machine for proper end-to-end testing of the bundled experience), we need `electron-builder` configured with cross-platform targets and real app icons replacing Electron's default penguin.

This is **slice 2 of N**. No code signing or notarization in this slice — those are explicitly deferred ("we will keep make electron prep job, don't need to worry about Apple license"). Stacks on `plan/desktop-electron-scaffold` (slice 1).

## Success criteria

- `electron-builder` is installed as a devDep of `@zwaggen/desktop`.
- An `electron-builder.yml` (or builder section in `package.json`) configures:
  - `appId: com.zwaggen.desktop`
  - `productName: Zwaggen`
  - macOS: `dmg` target, both `arm64` and `x64`, no signing (`identity: null`).
  - Windows: `nsis` installer + `zip` portable, `x64` only, no signing.
  - Linux: `AppImage` target, `x64` only.
  - `files`: includes `dist/**/*` (built main + preload), `package.json`, plus the built `apps/web/dist/**/*` (the renderer assets).
  - `extraResources`: empty for now.
  - Icon paths: `build/icon.icns` for mac, `build/icon.ico` for win, `build/icon.png` for Linux. (Or a single `build/icon.png` ≥ 1024×1024 — electron-builder will derive platform formats automatically; we use the explicit-per-OS form so future asset tweaks per platform are possible.)
- App icons exist at:
  - `apps/desktop/build/icon.png` (1024×1024 source PNG, baseline for Linux + auto-derive)
  - `apps/desktop/build/icon.icns` (multi-size macOS icon)
  - `apps/desktop/build/icon.ico` (multi-size Windows icon)
  - All generated from `apps/docs/public/favicon.svg` via a committed one-shot script `apps/desktop/scripts/build-icons.mjs` (so CI doesn't need to render SVGs).
- New `pnpm --filter @zwaggen/desktop build:icons` script regenerates icons on demand.
- New `pnpm --filter @zwaggen/desktop pack` script runs `electron-builder --dir` (unpacked build, fastest) for local smoke.
- New `pnpm --filter @zwaggen/desktop release` script runs `electron-builder --mac --win --linux` (cross-platform, real installers). Requires the host OS to support cross-build for those targets — documented in the README.
- `pnpm --filter @zwaggen/desktop pack` produces an unpacked Electron app under `apps/desktop/release/<platform>-unpacked/Zwaggen.app` (mac) or equivalent on win/linux. Verifying it launches: out of scope for unit tests, in-scope for the README runbook.
- The README documents:
  - The `pack` / `release` scripts.
  - Per-OS prereqs for cross-builds (e.g., on macOS you can build .dmg + .AppImage; on Linux you can build .AppImage but not .dmg without extra tooling).
  - That builds are unsigned and what that means (macOS Gatekeeper "damaged" warning, Windows SmartScreen warning).
  - That the `release/` directory is gitignored.
- Existing slice 1 tests still pass.
- TODO entry "Zwaggen Desktop slice 2 — packaging" ticked.

## Out of scope

- **Code signing / notarization** — explicitly deferred. The user will revisit when they decide to ship publicly.
- **Auto-update** (`electron-updater`) — depends on signing and a release server; future slice.
- **GitHub Releases publish workflow** — local builds only in this slice. No CI release step.
- **Per-OS package formats beyond the defaults**: no `.deb` / `.rpm` / Snap / Flatpak; no Windows MSI / portable beyond NSIS+zip; no macOS .pkg.
- **App icon redesign** — reuse the existing brand mark from `apps/docs/public/favicon.svg`. Just resize, don't redesign.
- **Splash screen, About dialog, dock menu** — UX polish for a later slice.
- **Reducing bundle size below electron-builder's defaults** — note as a follow-up if the .dmg ends up oversized.
- **Architecture combinations** beyond the listed ones (no Linux ARM, no Windows ARM, no macOS x64+arm64 universal binary — separate-architecture .dmgs are fine v0).

## Approach

### Files

**Create:**
- `apps/desktop/electron-builder.yml` — declarative builder config (preferred over `package.json` blob for diff readability).
- `apps/desktop/scripts/build-icons.mjs` — Node script using `sharp` + `png-to-ico` to render the SVG into per-OS icons.
- `apps/desktop/build/icon.png` — 1024×1024 PNG (committed, generated by the script).
- `apps/desktop/build/icon.ico` — multi-size .ico (committed, generated).
- `apps/desktop/build/icon.icns` — generated only when running on macOS (needs `iconutil` from Xcode Command Line Tools); committed if generated, else electron-builder falls back to deriving from `icon.png`.
- `apps/desktop/build/icons/` — folder of PNGs at sizes 16/32/48/64/128/256/512/1024 for Linux's `desktopIntegration` (electron-builder picks them up if it's a folder reference; not strictly needed since we provide a single PNG, but useful for crisp menu icons).

**Modify:**
- `apps/desktop/package.json` — add `electron-builder`, `sharp`, `png-to-ico` to devDeps; add `build:icons`, `pack`, `release` scripts.
- `apps/desktop/.gitignore` — add `release/` (electron-builder output) and `dist-electron/` (if any).
- `apps/desktop/README.md` — packaging section.
- `docs/TODO.md` — tick the slice 2 entry.

### `electron-builder.yml` shape

```yaml
appId: com.zwaggen.desktop
productName: Zwaggen
copyright: © 2026 Victor Liang
asar: true

directories:
  output: release
  buildResources: build

files:
  - dist/**/*              # built main.cjs + preload.cjs from tsup
  - package.json

extraResources:
  - from: ../web/dist
    to: web                # bundled apps/web at <Resources>/web/index.html

mac:
  category: public.app-category.developer-tools
  target:
    - target: dmg
      arch: [arm64, x64]
  identity: null           # unsigned for v0
  icon: build/icon.icns

win:
  target:
    - target: nsis
      arch: [x64]
    - target: zip
      arch: [x64]
  icon: build/icon.ico

linux:
  target:
    - target: AppImage
      arch: [x64]
  category: Development
  icon: build/icon.png

dmg:
  sign: false              # avoid signing prompt on dev machines
```

### Renderer asset path inside the package

Slice 1's `main.ts` resolves `apps/web/dist/index.html` via `path.join(__dirname, '..', '..', 'web', 'dist', 'index.html')`. That works in dev (when running from `apps/desktop/dist/` next to `apps/web/dist/`), but inside an `.app` bundle the layout is different — `__dirname` will be `<Resources>/app.asar/dist/` and `apps/web/` doesn't exist next to it. The `extraResources` config above puts the renderer at `<Resources>/web/`, which from `__dirname` is `../../web/index.html`.

But there's a small wrinkle: when running unpacked locally (slice 1 `pnpm dev`/`start`), the path is different from inside a packaged app. Solution: detect packaged vs unpacked and resolve accordingly.

```ts
// apps/desktop/electron/main.ts
function resolveRendererIndex(): string {
  if (app.isPackaged) {
    // In packaged mode, extraResources places web/ at <Resources>/web/
    return path.join(process.resourcesPath, 'web', 'index.html');
  }
  // Unpacked dev/start: walk up from apps/desktop/dist/ to apps/web/dist/
  return path.join(__dirname, '..', '..', 'web', 'dist', 'index.html');
}
```

This is a small slice-2 modification to `main.ts`.

### Icon generation script

```js
// apps/desktop/scripts/build-icons.mjs
import sharp from 'sharp';
import pngToIco from 'png-to-ico';
import { mkdir, writeFile } from 'node:fs/promises';
import { resolve } from 'node:path';

const SRC = resolve(import.meta.dirname, '..', '..', 'docs', 'public', 'favicon.svg');
const OUT = resolve(import.meta.dirname, '..', 'build');
const ICONS = resolve(OUT, 'icons');
const SIZES = [16, 32, 48, 64, 128, 256, 512, 1024];

await mkdir(ICONS, { recursive: true });

// Per-size PNGs (also useful for Linux desktop entries)
const buffers = await Promise.all(
  SIZES.map(async (size) => {
    const buf = await sharp(SRC).resize(size, size).png().toBuffer();
    await writeFile(resolve(ICONS, `${size}x${size}.png`), buf);
    return { size, buf };
  }),
);

// Linux baseline + electron-builder fallback source
await writeFile(resolve(OUT, 'icon.png'), buffers.find((b) => b.size === 1024).buf);

// Windows .ico (multi-size)
const icoSizes = [16, 32, 48, 64, 128, 256];
const icoBuf = await pngToIco(icoSizes.map((s) => resolve(ICONS, `${s}x${s}.png`)));
await writeFile(resolve(OUT, 'icon.ico'), icoBuf);

// macOS .icns: only generate when on macOS (needs iconutil). When absent,
// electron-builder derives .icns from build/icon.png automatically.
if (process.platform === 'darwin') {
  const { execFile } = await import('node:child_process');
  const { promisify } = await import('node:util');
  const exec = promisify(execFile);
  const iconset = resolve(OUT, 'icon.iconset');
  await mkdir(iconset, { recursive: true });
  // iconutil expects icon_<size>x<size>.png and icon_<size>x<size>@2x.png pairs
  const macSizes = [16, 32, 64, 128, 256, 512, 1024];
  for (const s of macSizes) {
    if (s !== 1024) await writeFile(resolve(iconset, `icon_${s}x${s}.png`), buffers.find((b) => b.size === s).buf);
    if (s !== 16) await writeFile(resolve(iconset, `icon_${s/2}x${s/2}@2x.png`), buffers.find((b) => b.size === s).buf);
  }
  await exec('iconutil', ['-c', 'icns', '-o', resolve(OUT, 'icon.icns'), iconset]);
}

console.log('Icons generated to', OUT);
```

`build:icons` runs this. The committed outputs let CI / non-mac contributors skip running it.

### Why per-OS targets are minimal

- macOS: `dmg` only (no `.zip` — most users want the `.dmg` mounting experience). Both `arm64` and `x64` because Apple Silicon adoption is high and Rosetta translation hurts startup.
- Windows: `nsis` is the standard installer + `zip` for portable users (no install, just unzip and run).
- Linux: `AppImage` only (no `.deb`/`.rpm`/Snap/Flatpak — those each need their own packaging quirks; AppImage works everywhere with one file).

### Cross-build constraints

`electron-builder` can build:
- macOS targets: only on macOS (codesign, dmg, etc.)
- Windows targets: on Windows natively, OR on macOS/Linux with Wine (electron-builder handles this automatically, but slow).
- Linux targets: on macOS or Linux. (Windows can do it with WSL.)

For slice 2 (local-dev), we don't ship anywhere — we just need `pnpm pack` and `pnpm release` to *work* on whichever OS the developer is running. Document that "release" outputs on the host OS first; cross-OS builds are best-effort. CI will likely use a matrix in a future slice.

### Test strategy

- **No new unit tests** — electron-builder is a build tool, not a runtime; testing it via vitest would mean asserting against its config which is brittle.
- **The packaging itself is the test.** Acceptance is "running `pnpm --filter @zwaggen/desktop pack` on macOS produces `release/mac-arm64/Zwaggen.app` that launches and shows the UI." Manual smoke runbook in the README.
- **Existing slice 1 tests keep running** — no behaviour changes affect them.
- **One small assertion** can land: a vitest check that `apps/desktop/electron-builder.yml` parses and contains the expected `appId` / `productName`. Cheap insurance against accidental config corruption.

### Risks

- **electron-builder size bloat**. Default unpacked `.app` for an Electron app is ~200MB. Acceptable for v0; revisit if it gets larger than that.
- **`extraResources` path drift**. The `from: ../web/dist` is relative to `apps/desktop/`. If `apps/web` is renamed, this breaks. Low risk; called out in the config comment.
- **Asar packing**. `asar: true` means the app's source is in `app.asar`. Native modules (none today) would need `asarUnpack`. We have zero native deps, so this is fine.
- **Icon generation needs `sharp`**. `sharp` has prebuilt binaries for major platforms but historically has been a source of pain (`sharp@0.34.5` is already in the workspace, and `png-to-ico@3.0.1` too — both confirmed). Builders that fall back to running the icon script need these to install correctly. CI is unaffected because we commit the generated icons.
- **`iconutil` only on macOS**. The script gracefully skips .icns generation off-mac and electron-builder derives one from `icon.png` automatically. Builds on Linux/Windows therefore won't ship a hand-tuned .icns but will still produce a valid macOS icon (less crisp at small sizes, acceptable for v0).
- **Stacked branch ordering**. PR for slice 2 must be opened with base = `plan/desktop-electron-scaffold`. Once slice 1 merges, GitHub auto-rebases.
